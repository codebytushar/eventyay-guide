2. First-Time Setup (Step-by-Step)

Step 1 Clone Your Fork & Configure Remotes

Open PowerShell or terminal in your desired working folder (e.g. C:\Projects):

# 1. Log in to GitHub if not already authenticated
gh auth login

# 2. Clone your personal fork
git clone https://github.com/<YOUR_GITHUB_USERNAME>/eventyay.git
cd eventyay

# 3. Add the official upstream repository to keep your fork updated
git remote add upstream https://github.com/fossasia/eventyay.git

# 4. Fetch upstream branches and ensure you are on dev
git fetch upstream
git checkout dev
git pull upstream dev

Step 2 Create Local Environment File

# PowerShell (Windows)
Copy-Item deployment\env.dev.sample .env.dev

# Bash (macOS / Linux)
cp deployment/env.dev.sample .env.dev

Step 3 ⚠️ Critical Windows Fix: CRLF to LF Conversion

⚠️
Windows Gotcha: Git on Windows checks out shell scripts with CRLF (\r\n). Because docker-compose.yml volume-mounts ./app/entrypoint.sh directly into the container, a CRLF line ending causes the container to immediately crash with:
exec /usr/src/app/entrypoint.sh: no such file or directory.

Run this one-line command in PowerShell to convert the file to pure Unix LF:

$content = [System.IO.File]::ReadAllText("app\entrypoint.sh").Replace("`r`n", "`n"); [System.IO.File]::WriteAllText("app\entrypoint.sh", $content, (New-Object System.Text.UTF8Encoding($false)))

Step 4 Start Docker Compose Stack

Build the images and start the full background development stack:

docker compose up -d --build

Monitor startup progress (takes 5-7 minutes initially):

docker logs -f eventyay-next-web

Step 5 Create Local Admin Account

docker exec -i eventyay-next-web python manage.py shell -c "from eventyay.base.models import User; u = User.objects.create_adminuser(email='admin@eventyay.local', password='EventyayAdmin123!'); print('Admin created:', u.email)"
✅
Default Admin Credentials:
Email: admin@eventyay.local  |  Password: EventyayAdmin123!

3. 🔄 Regular Day-to-Day Development Routine

Because app/eventyay is volume-mounted live into the container, you almost never need to rebuild Docker for everyday programming!

3.1 Daily Start & Stop Routine

Action Command What It Does
Start Working (Morning) docker compose up -d Spins up all containers in 2-3 seconds. No rebuild needed. All database users, events, and records are preserved.
Pause / Finish (Evening) docker compose stop Pauses running containers without deleting them. Next start is instantaneous.
Clean Stop (Free RAM) docker compose down Stops and removes container processes, but keeps your database data in named Docker volumes.
🛑
The Golden Rule: NEVER run docker compose down -v during daily work! The -v flag completely deletes all database volumes, permanently erasing all your local test events, accounts, and settings.

3.2 Live Reloading (Instant Feedback)

  • Python Code & Django HTML Templates (app/eventyay/): The server watches for changes automatically. The moment you save any file in your editor, Django reloads within 1-2 seconds. Simply refresh your browser tab.
  • Vue / Frontend Components (app/eventyay/webapp/): Vite dev servers run with Hot-Module Replacement (HMR). Changes update live in the browser without even requiring a full page refresh.

3.3 When to Rebuild vs When Not to

Scenario Command to Run Why
Daily code editing Nothing! Just save your file. Mounted directly from your host disk into the container.
Pulled new updates from upstream docker compose up -d --build
docker exec -it eventyay-next-web python manage.py migrate		 Re-syncs Python packages (uv) and applies new database migrations.
Created or altered a Django Model docker exec -it eventyay-next-web python manage.py makemigrations
docker exec -it eventyay-next-web python manage.py migrate		 Generates and applies database schema migrations in PostgreSQL.
Server hung or unresponsive docker restart eventyay-next-web Fast restart of only the web service (~5 seconds).
CSS styles not updating docker exec -it eventyay-next-web python manage.py compress --force Recompiles compressed static stylesheets.

3.4 Running Tests Before Submitting Code

Always verify tests pass inside the container before committing changes:

# Run the full test suite
docker exec -it eventyay-next-web pytest tests/

# Run tests for a specific module (e.g. organizer speaker tests)
docker exec -it eventyay-next-web pytest tests/orga/

3.5 Daily Git Contribution Workflow

Step-by-Step Feature Workflow:

# 1. Start containers
docker compose up -d

# 2. Sync dev branch with upstream
git checkout dev
git pull upstream dev

# 3. Create a feature branch for your issue
git checkout -b feature/my-issue-fix

# 4. Make code edits, test in browser at http://localhost:8000

# 5. Run tests
docker exec -it eventyay-next-web pytest tests/

# 6. Commit and push to your fork
git add .
git commit -m "fix(orga): resolve issue with table sorting"
git push -u origin feature/my-issue-fix

# 7. Open Pull Request on GitHub against fossasia/eventyay:dev

6. Troubleshooting Common Issues

`no such file or directory: entrypoint.sh`

Cause: Windows CRLF line endings inside app/entrypoint.sh.

Fix: Run the PowerShell line-ending fix in Step 3, then run docker compose up -d.

`failed to connect to docker API`

Cause: Docker Desktop daemon is stopped.

Fix: Start Docker Desktop from the Start menu and wait until the whale icon is steady green.

Missing CSS / MIME Type Error

Cause: Cached or uncompiled static CSS assets.

Fix: Run docker exec -it eventyay-next-web python manage.py compress --force and hard refresh with Ctrl + Shift + R.
